# ZeroOS v0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make ZeroOS remember. Three things persist across sessions — a capped list of facts the user explicitly approved, a transcript of past turns that is displayed but never sent to the model, and a usage line that says whether anyone came back. The user can see all of it and delete any of it without a terminal.

**Architecture:** v0.1's five layers are unchanged and dependencies still point strictly downward. v0.2 adds one store per kind of persistence in `agent/`, two catalog functions in `catalog/`, two dialog rows in `policy/`, a settings file in `platform/`, and one pane in `surface/`. The only structural change is that `agent/session.py` sends **two** system messages instead of one.

**Tech Stack:** Unchanged — Python 3.11+, `openai` SDK pointed at OpenRouter, PyGObject (GTK4 + libadwaita + GIO + libsecret), pytest, Flatpak.

**Provider note:** the memory block is a second `{"role": "system"}` message appended after the fixed prompt, not interpolated into it. `agent/session.py` remains the only file that knows a wire format exists.

**Spec:** [`docs/superpowers/specs/2026-08-03-zeroos-v02-design.md`](../specs/2026-08-03-zeroos-v02-design.md). Section references below (§4, §6, …) point there. v0.1's spec is still in force for everything this one does not change.

## Global Constraints

Every task's requirements implicitly include this section. **v0.1's Global Constraints all still apply** — they are not repeated here except where v0.2 adds to them.

- **Dependencies are still frozen at three.** `openai`, PyGObject, `pytest`. Memory is JSON Lines through `json` and `pathlib`; the pane is GTK widgets already in use. No `pydantic` models of our own, no JSON store library, no `platformdirs`.
- **`SYSTEM_PROMPT` is never interpolated.** Memory goes in a second message. The form-of-address variants are built once at import time into fixed strings; nothing builds a prompt per turn. A `.format()` or f-string evaluated inside `send()` or the step loop is a defect, not a style choice.
- **Exactly eighteen tools** after Task 4, with the names and tiers in spec §4. `tests/test_registry.py` fails if the catalog and the tier table disagree in either direction.
- **`remember` and `forget` are both `confirm`.** Neither may ever be `auto`, in any task, for any reason. See spec §6.
- **Store functions never raise into the agent loop.** Same rule as v0.1's catalog functions, extended to `platform/memory.py`: every failure path returns a value. `tests/test_catalog_contract.py::test_no_tool_ever_raises_on_hostile_arguments` will feed both new tools garbage automatically once they are registered.
- **Never call `Path.expanduser()`, `os.path.expanduser()`, or `Path.home()`.** Use `paths.data_dir()` and `paths.config_dir()`, which already honour `ZEROOS_HOME` and the XDG overrides the tests depend on.
- **Everything persisted lives under `paths.data_dir()` or `paths.config_dir()`.** Both are already denied by the path sandbox, which is what keeps `read_text_file` and `write_text_file` away from memory. Do not put any of these files anywhere else.
- **Writes are atomic.** Write to a sibling temp file, then `os.replace`. A half-written `memory.jsonl` after a crash is a corrupted fact list.
- **Fact text is never rendered as markup — and the two widget families default in opposite directions.** Row text and fact text are attacker-influenced (spec §6), and a fact containing `<span foreground="…">` that renders as markup is a fact the user cannot see in the very pane that exists to let them find and remove it.
  - `dialog.py` builds each row as `Gtk.CheckButton(label=…)`, which does **not** interpret markup unless `use-markup` is turned on. Nothing to do; do not turn it on.
  - `Adw.PreferencesRow` — the base of `Adw.ActionRow`, used by the recall pane in Task 9 — has `use-markup` defaulting to **TRUE**. Not enabling it is not enough: set `use_markup=False` explicitly on every row whose title or subtitle carries a fact or a past message.
- **No message content in `usage.log`.** Timestamps and counts only.
- **Commits go on `main`.** Do not create feature branches.
- **Every commit message ends with:**
  ```
  Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
  ```


**Why split this way.** Three stores rather than one because the three kinds of persistence have three different rules — memory is injected and capped, history is displayed and never injected, usage has no content at all. A single `persistence.py` holding all three would put the rule that matters most (history never reaches the model) inside a module that also feeds prompt text, one careless line away from being wrong. Separate files make the isolation something you can read off the imports: `session.py` imports `memory.load`, and nothing anywhere imports history into a request.

**Why the fact store lives in `platform/`.** It is pure file I/O over `paths`, exactly what `platform/` is for — and, decisively, `policy/describe.py` has to read it to render the dialog row (Task 5). v0.1's spec §2 fixes the dependency order as `surface` → `agent` → `policy`/`catalog` → `platform`; a store under `agent/` would make `describe` import upward and break that order on its first offence. Under `platform/` the import is downward, the same shape as `sandbox.py` → `paths.py`.

The consequence: the store holds no prompt text. `MEMORY_PREFACE` stays in `agent/prompt.py` and `session.py` assembles the injected block from `prompt.MEMORY_PREFACE` plus `memory.load()` (Task 8). The store never imports `agent`.

`catalog/memory.py` and `platform/memory.py` share a name deliberately — it matches the existing `catalog/files.py` ↔ `platform/files.py` mirroring. Inside `catalog/memory.py`, import the store as `from zeroos.platform import memory as store`.

```python
# zeroos/platform/settings.py
"""User preferences. One key in v0.2: how ZeroOS addresses you.

Anything unreadable, unparseable, or unrecognised resolves to "sir", which is
v0.1's hardcoded behaviour. An absent settings file therefore changes nothing.
"""

import json
import os
from pathlib import Path

from zeroos.platform import paths

ADDRESSES = ("sir", "maam", "none")
DEFAULT = "sir"


def path() -> Path:
    return paths.config_dir() / "settings.json"


def _load() -> dict:
    try:
        data = json.loads(path().read_text(encoding="utf-8"))
    except (OSError, ValueError):
        return {}
    return data if isinstance(data, dict) else {}


def address() -> str:
    value = _load().get("address")
    return value if value in ADDRESSES else DEFAULT


def set_address(value: str) -> None:
    """Raises on an unknown value. Only the recall pane calls this; it is not
    reachable from the model, so failing loudly is safe here."""
    if value not in ADDRESSES:
        raise ValueError(f"unknown form of address: {value!r}")
    _save({**_load(), "address": value})


def _save(data: dict) -> None:
    target = path()
    target.parent.mkdir(parents=True, exist_ok=True)
    temp = target.with_name(target.name + ".tmp")
    temp.write_text(json.dumps(data), encoding="utf-8")
    os.replace(temp, target)
```

## Task 3: The memory store

Spec §3.

**Files:**
- Create: `zeroos/platform/memory.py`
- Test: `tests/test_memory.py`

**Interfaces:**
- Consumes: `paths.data_dir`
- Produces: `memory.MAX_FACTS`, `memory.MAX_CHARS`, `memory.path()`, `memory.normalise(text)`, `memory.load()`, `memory.add(text) -> str`, `memory.remove(fact_id) -> bool`, `memory.text_of(fact_id) -> str | None`

**Why `platform/` and not `agent/`.** Three modules read this store: `catalog/memory.py`, `policy/describe.py`, and `session.py`. Under `agent/` the second of those would be a `policy` → `agent` import, which inverts the dependency order v0.1's spec §2 fixes. Under `platform/` all three point downward. The store therefore holds no prompt text: it knows about facts and a file, and `session.py` (Task 8) is what turns facts into a prompt block.

**Why reject and never evict.** Dropping the oldest fact to make room deletes something the user ticked a dialog to approve, and tells them nothing. Rejecting is louder and correct: the caller turns it into a sentence the model reads and repeats. `add` therefore assumes its caller has already checked the caps — the checks live in the catalog layer (Task 4) where there is a string to return.

**Why the file lives in `data_dir()`.** The path sandbox already denies that directory, so `read_text_file` and `write_text_file` cannot reach `memory.jsonl`. The two catalog functions are the only write route. This is asserted in Task 4's tests, not assumed here.

```python
# zeroos/platform/memory.py
"""The fact store. Spec §3.

Lives in data_dir(), which the path sandbox already denies, so the model
cannot reach this file through read_text_file or write_text_file. The two
catalog functions in catalog/memory.py are the only write route, and both
are confirm-tier.

Nothing here raises into the agent loop. Caps are checked by the caller,
which has a string to return; add() assumes the check has happened.

This is the bottom layer: facts and a file, no prompt text. session.py
assembles the injected block from prompt.MEMORY_PREFACE and load(), which
is what lets policy/describe.py read facts without importing the agent.
"""

import json
import os
import secrets
from datetime import datetime, timezone
from pathlib import Path

from zeroos.platform import paths

MAX_FACTS = 50
MAX_CHARS = 200

# Control characters that are not whitespace. Tabs and newlines survive this
# and are collapsed by the split() below; the rest are deleted, because a
# fact carrying terminal escapes is a fact meant to be read by something
# other than a human.
_STRIP = {c: None for c in range(32) if chr(c) not in " \t\n\r\v\f"} | {127: None}


def path() -> Path:
    return paths.data_dir() / "memory.jsonl"


def normalise(text: str) -> str:
    """Collapse whitespace, strip control characters. Runs before the length
    check, so the characters counted are the characters displayed."""
    return " ".join(str(text).translate(_STRIP).split())


def load() -> list[dict]:
    try:
        raw = path().read_text(encoding="utf-8")
    except OSError:
        return []
    facts = []
    for line in raw.splitlines():
        if not line.strip():
            continue
        try:
            fact = json.loads(line)
        except ValueError:
            continue
        if isinstance(fact, dict) and isinstance(fact.get("id"), str) and isinstance(fact.get("text"), str):
            facts.append(fact)
    return facts


def add(text: str) -> str:
    """Store a normalised fact and return its id. The caller checks the caps."""
    fact = {
        "id": secrets.token_hex(4),
        "text": text,
        "created": datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ"),
    }
    _write(load() + [fact])
    return fact["id"]


def remove(fact_id: str) -> bool:
    facts = load()
    kept = [f for f in facts if f["id"] != fact_id]
    if len(kept) == len(facts):
        return False
    _write(kept)
    return True


def text_of(fact_id: str) -> str | None:
    for fact in load():
        if fact["id"] == fact_id:
            return fact["text"]
    return None


def _write(facts: list[dict]) -> None:
    target = path()
    target.parent.mkdir(parents=True, exist_ok=True)
    temp = target.with_name(target.name + ".tmp")
    temp.write_text("".join(json.dumps(f) + "\n" for f in facts), encoding="utf-8")
    os.replace(temp, target)
```

## Task 4: remember and forget — the catalog grows to eighteen

Spec §4, §6.

**Files:**
- Create: `zeroos/catalog/memory.py`
- Modify: `zeroos/policy/tiers.py`, `zeroos/catalog/registry.py`
- Test: `tests/test_catalog_memory.py`, `tests/test_registry.py` (modify), `tests/test_sandbox.py` (modify)

**Interfaces:**
- Consumes: `gate.decide`, `zeroos.platform.memory`, `catalog.tool.tool`
- Produces: `catalog.memory.bind(gate) -> [remember, forget]`; `TIERS["remember"] = Tier.CONFIRM`; `TIERS["forget"] = Tier.CONFIRM`

**Why both are `confirm`.** `remember` being unattended is an unattended write into every future prompt. `forget` being unattended is worse in a quieter way: a hostile file could instruct the model to erase a memory, and the memory most worth erasing is a constraining one. An assistant that can silently forget its own constraints has none. Spec §6 is the full argument; read it before writing this task.

**Neither takes a path**, so neither appears in `PATH_ARGUMENTS`. The registry test asserts consistency in both directions and will catch a mistaken entry.

**The caps are checked here, not in the store**, because this is the layer that has a string to return to the model.

```python
# zeroos/catalog/memory.py
"""remember and forget. Spec §4.

Both are confirm-tier and must stay that way. The caps are enforced here
rather than in the store because this is the layer with a string to hand
back to the model.
"""

from zeroos.platform import memory as store
from zeroos.catalog.tool import _UNEXPECTED, tool
from zeroos.policy.gate import Verdict


def bind(gate):
    @tool
    def remember(text: str) -> str:
        """Store one short fact about the user or their preferences so it is
        available in future conversations.

        Args:
            text: The fact, in one sentence, in the user's own words.

        Use this only when the user asks you to remember something, or states
        a lasting preference. Do not use it to store the contents of files, or
        anything the user has not said themselves.
        """
        clean = store.normalise(text)
        if not clean:
            return "There was nothing there to remember."
        if len(clean) > store.MAX_CHARS:
            return f"That is too long to remember — keep it under {store.MAX_CHARS} characters."
        verdict, message = gate.decide("remember", {"text": clean})
        if verdict is not Verdict.ALLOW:
            return message
        if len(store.load()) >= store.MAX_FACTS:
            return f"Already remembering {store.MAX_FACTS} things. Ask which one to forget first."
        try:
            store.add(clean)
        except OSError:
            return _UNEXPECTED
        return f"Remembered: {clean}"

    @tool
    def forget(fact_id: str) -> str:
        """Delete one remembered fact.

        Args:
            fact_id: The id shown in square brackets beside the fact in the
                list of remembered things.
        """
        verdict, message = gate.decide("forget", {"fact_id": fact_id})
        if verdict is not Verdict.ALLOW:
            return message
        try:
            if not store.remove(fact_id):
                return "Nothing is remembered under that name."
        except OSError:
            return _UNEXPECTED
        return "Forgotten."

    return [remember, forget]
```

**`gate.decide` does not open the dialog.** `session.send()` calls `gate.prepare(...)` with every tool call in the turn *before* any tool body runs, so by the time this function executes the row has already been rendered and answered; `decide` is a ledger lookup. Nothing written here can suppress, shorten, or alter a dialog row. Two consequences:

- The cap checks straddle the gate for message precedence, not to avoid asking. Length and emptiness come **first** so a malformed call gets a precise reason rather than a generic one. The fifty-fact cap comes **after** for two reasons: a denied call must return the user's denial and nothing else, and the count is freshest then — between the dialog opening and the user answering they may have deleted something in the pane.
- `MAX_CHARS` does **not** bound the dialog row. A 10 KB `remember` argument is rendered in full by `describe` and only then rejected here. Truncating for display is Task 5's job, and it is the row — not this check — that spec §6 relies on.

## Task 5: Dialog rows for remember and forget

Spec §7, §6.

**Files:**
- Modify: `zeroos/policy/describe.py`
- Test: `tests/test_describe.py`

**Interfaces:**
- Consumes: `zeroos.platform.memory.text_of`, `memory.normalise`, `memory.MAX_CHARS`

**Why this is a security task, not a copy task.** `_single` falls through to `f"Run {tool}"` for anything it does not know. Left alone the dialog says **"Run remember"** — which breaks v0.1 §4.4's no-jargon rule and, worse, hides the exact text spec §6 requires the user to read before approving. The row *is* the defence. `forget` resolves the id back to the fact's text for the same reason: `Forget a1b2c3d4` asks the user to approve something they cannot evaluate.

**Why the truncation lives here.** `describe` runs before the tool body, so `catalog/memory.py`'s `MAX_CHARS` check cannot keep a row short — a 10 KB argument would be rendered in full and only rejected afterwards. Truncate at the display layer, where the length actually matters, and mark the cut with `…` so a wall of text reads as a wall of text rather than as a short fact.

**Why `policy` may import `platform`.** v0.1 spec §2 orders the layers `surface` → `agent` → `policy`/`catalog` → `platform`. `policy/sandbox.py` already imports `platform/paths.py`; this is the same downward edge. It is also why Task 3 puts the store in `platform/` — from `agent/` this import would be the first upward one in the tree.

```python
# zeroos/agent/history.py
"""Past turns. Spec §9.

Persisted so the conversation survives a restart, displayed in the recall
pane, and never read back into a prompt. The only importer of this module
is surface/recall.py, plus the one line in session.py that writes to it.

What is stored is what the window showed: the user's text and the reply.
Not session._messages, which is full of empty assistant content and tool
results.
"""

import json
import os
from datetime import datetime, timezone
from pathlib import Path

from zeroos.platform import paths

MAX_TURNS = 500


def path() -> Path:
    return paths.data_dir() / "history.jsonl"


def load() -> list[dict]:
    try:
        raw = path().read_text(encoding="utf-8")
    except OSError:
        return []
    turns = []
    for line in raw.splitlines():
        if not line.strip():
            continue
        try:
            turn = json.loads(line)
        except ValueError:
            continue
        if isinstance(turn, dict) and "you" in turn and "zeroos" in turn:
            turns.append(turn)
    return turns


def append(you: str, zeroos: str) -> None:
    turn = {
        "at": datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ"),
        "you": you,
        "zeroos": zeroos,
    }
    _write((load() + [turn])[-MAX_TURNS:])


def clear() -> None:
    _write([])


def _write(turns: list[dict]) -> None:
    target = path()
    target.parent.mkdir(parents=True, exist_ok=True)
    temp = target.with_name(target.name + ".tmp")
    temp.write_text("".join(json.dumps(t) + "\n" for t in turns), encoding="utf-8")
    os.replace(temp, target)
```

```python
# zeroos/agent/usage.py
"""One line per session. Spec §9.

Separate from actions.log because that file answers one question — what did
ZeroOS do to my computer — and it answers it faster if every line means the
same thing.

Counts and timestamps only. No message content, no fact text, no filenames.
If you are about to add a field here, check that it is a number.
"""

from datetime import datetime, timezone
from pathlib import Path

from zeroos.platform import paths


def path() -> Path:
    return paths.data_dir() / "usage.log"


def record(started: datetime, turns: int, actions: int, declined: int) -> None:
    """Never raises. A failure to record usage must not take the app down on
    the way out."""
    ended = datetime.now(timezone.utc)
    line = (
        f"{_stamp(started)} ended={_stamp(ended)} "
        f"turns={turns} actions={actions} declined={declined}\n"
    )
    try:
        _append(line)
    except OSError:
        pass


def _append(line: str) -> None:
    target = path()
    target.parent.mkdir(parents=True, exist_ok=True)
    with target.open("a", encoding="utf-8") as handle:
        handle.write(line)


def _stamp(moment: datetime) -> str:
    return moment.strftime("%Y-%m-%dT%H:%M:%SZ")
```

1. The prompt is resolved **once, in `__init__`**, into `self._prompt`. Not per turn, not per step.
2. The memory block is built **inside the step loop**, so a `remember` approved mid-turn is visible to the very next model call in the same turn. Building it once per `send()` would make a just-approved fact invisible until the user typed again, which reads as the assistant forgetting something it just confirmed. The block is assembled here — `prompt.MEMORY_PREFACE` plus `memory.load()` — because the store lives in `platform/` and holds no prompt text (Task 3).
3. `send()` appends the completed turn to history.
4. `close()` writes the usage line.

**What must not change:** with no memories stored, the outgoing request is byte-identical to v0.1's. One system message, same content. This is spec §13.4 and it has its own test.

**`history` is never read here.** The test asserting so inspects the entire request body, not a flag — a flag would only prove that whoever wrote the flag believed it.

```python
    @staticmethod
    def _memory_messages() -> list[dict]:
        """The second system message, or nothing at all.

        Read inside the step loop, not once per turn: a remember approved
        halfway through a turn must be visible to the next model call in that
        same turn, or the assistant appears to forget what it just confirmed.

        Empty means omitted, not sent blank — a fresh install's request is
        byte-identical to v0.1's.

        The preface lives in prompt.py and the facts in platform/memory.py;
        joining them is this layer's job, which is what keeps the store free
        of prompt text and importable from policy/describe.py.
        """
        facts = memory.load()
        if not facts:
            return []
        lines = "\n".join(f"[{f['id']}] {f['text']}" for f in facts)
        return [{"role": "system", "content": f"{MEMORY_PREFACE}\n\n{lines}"}]
```

```python
# zeroos/surface/recall.py
"""The memory and history pane. Spec §10.

This pane is what makes spec §6's secondary defences real: a fact that got
through a carelessly-ticked dialog has to be findable and removable without
a terminal.

Deletion here does not pass through the gate. It is the user acting, not the
model — the same asymmetry as the user dragging a file to the trash.

Fact text and past messages are attacker-influenced (spec §6), and
Adw.PreferencesRow:use-markup defaults to TRUE — so every row carrying that
text sets use_markup=False explicitly. Not enabling it is not enough.
"""

import gi

gi.require_version("Adw", "1")
gi.require_version("Gtk", "4.0")
from gi.repository import Adw, Gtk  # noqa: E402

from zeroos.agent import history  # noqa: E402
from zeroos.platform import memory, settings  # noqa: E402

_ADDRESS_LABELS = {"sir": "Sir", "maam": "Ma'am", "none": "No title"}


def forget(fact_id: str) -> None:
    memory.remove(fact_id)


def forget_everything() -> None:
    for fact in memory.load():
        memory.remove(fact["id"])


def clear_history() -> None:
    history.clear()


def choose_address(value: str) -> None:
    settings.set_address(value)


def build(parent) -> Adw.PreferencesDialog:
    dialog = Adw.PreferencesDialog(title="What ZeroOS knows")
    page = Adw.PreferencesPage()
    page.add(_memory_group(dialog))
    page.add(_history_group(dialog))
    page.add(_settings_group(dialog))
    dialog.add(page)
    return dialog


def _memory_group(dialog) -> Adw.PreferencesGroup:
    group = Adw.PreferencesGroup(
        title="Remembered",
        description="Things you asked ZeroOS to remember. It is told these every time you talk to it.",
    )
    facts = memory.load()
    if not facts:
        group.add(Adw.ActionRow(title="ZeroOS hasn't been asked to remember anything yet."))
        return group
    for fact in facts:
        # use_markup=False is load-bearing, not tidiness: it defaults to True
        # on Adw.PreferencesRow, and a fact wrapped in <span> would render
        # invisible in the screen that exists so the user can delete it.
        row = Adw.ActionRow(
            title=fact["text"], subtitle=fact.get("created", ""), use_markup=False
        )
        row.set_property("title-lines", 0)
        button = Gtk.Button(icon_name="user-trash-symbolic", valign=Gtk.Align.CENTER)
        button.connect("clicked", lambda _b, i=fact["id"]: _forget_row(dialog, i))
        row.add_suffix(button)
        group.add(row)
    group.add(_danger_row("Forget everything", lambda: _confirm(dialog, forget_everything)))
    return group


def _history_group(dialog) -> Adw.PreferencesGroup:
    group = Adw.PreferencesGroup(
        title="Past conversations",
        description="Kept so you can look back. ZeroOS is not told any of this.",
    )
    turns = history.load()
    if not turns:
        group.add(Adw.ActionRow(title="Nothing here yet."))
        return group
    for turn in reversed(turns):
        row = Adw.ActionRow(title=turn["you"], subtitle=turn["zeroos"], use_markup=False)
        row.set_property("title-lines", 0)
        row.set_property("subtitle-lines", 0)
        group.add(row)
    group.add(_danger_row("Clear history", lambda: _confirm(dialog, clear_history)))
    return group


def _settings_group(dialog) -> Adw.PreferencesGroup:
    group = Adw.PreferencesGroup(title="Settings")
    row = Adw.ComboRow(title="How ZeroOS addresses you")
    row.set_model(Gtk.StringList.new([_ADDRESS_LABELS[key] for key in settings.ADDRESSES]))
    row.set_selected(settings.ADDRESSES.index(settings.address()))
    row.connect(
        "notify::selected",
        lambda r, _p: choose_address(settings.ADDRESSES[r.get_selected()]),
    )
    dialog._address_row = row
    group.add(row)
    return group


def selected_address(dialog) -> str:
    return settings.ADDRESSES[dialog._address_row.get_selected()]
```
