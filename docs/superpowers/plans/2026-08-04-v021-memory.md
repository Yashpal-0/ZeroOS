# ZeroOS v0.2.1 Memory Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make ZeroOS use what it remembers, propose facts on its own, hold more of them, and offer a summary when a session ends — every one of them still passing through the single approval dialog that already exists.

**Architecture:** One new module (`zeroos/agent/notice.py`) makes a second model call after each turn over a *filtered* transcript — user messages and assistant prose only, never tool results — and returns up to two candidate facts. Those candidates are held on the `Session` and surfaced at the start of the *next* turn as ordinary `remember` rows in the existing batched dialog, where every memory row now starts unticked. Caps rise to 150 facts of 300 characters, and window close runs one final summary turn off the main thread.

**Tech Stack:** Python 3, GTK4 + libadwaita (PyGObject), `openai` client against OpenRouter, pytest.

**Spec:** [`docs/superpowers/specs/2026-08-04-zeroos-v021-memory-design.md`](../specs/2026-08-04-zeroos-v021-memory-design.md)

## Global Constraints

- **Run tests with `/usr/bin/python3 -m pytest`.** The default `python3` on PATH is a Homebrew build with no `gi`; all fourteen GTK test modules fail collection under it.
- **Commit directly to `main`.** No feature branches in this repo.
- **No function in `zeroos/catalog/`, `zeroos/agent/notice.py`, or `Session.close()` may raise into the agent loop.** Bare `except Exception` where the spec says so.
- **`_TEXT` in `zeroos/agent/prompt.py` must not change.** v0.2 success criterion 4 requires a fresh install's request to be byte-identical to v0.1's. Only `MEMORY_PREFACE` may be edited.
- **`PROMPTS` stays built once at import.** Nothing constructs a prompt per turn.
- **No `Path.expanduser()`, `os.path.expanduser()`, or `Path.home()` outside `sandbox.resolve`.** Use `paths.home()`.
- **The Semgrep PreToolUse hook hard-blocks `subprocess` with `shell=True`.** Use the list form `["/bin/sh", "-c", cmd]`.
- **No cost, token, or latency figures** in code comments or docs. They have not been measured.
- **Model id is `qwen/qwen3.7-flash`**, base URL `https://openrouter.ai/api/v1`, both already in `session.py`.
- Existing dialog copy rules hold: folder names never full paths, counts past three, no jargon, the trash reassurance is permanent.

## File Structure

| File | Responsibility | Task |
|---|---|---|
| `zeroos/platform/memory.py` | store + caps. Two constants change. | 1 |
| `zeroos/agent/prompt.py` | `MEMORY_PREFACE` gains one sentence. | 2 |
| `zeroos/policy/gate.py` | pairs each row with its initial tick state before calling `_ask`. | 3 |
| `zeroos/surface/dialog.py` | reads that tick state into `Gtk.CheckButton(active=…)`. | 3 |
| `zeroos/agent/notice.py` | **new.** One function: filtered transcript in, candidate strings out. Knows nothing about the gate, the store, or GTK. | 4 |
| `zeroos/agent/session.py` | holds pending candidates, offers them at the top of `send()`, runs the closing summary. | 5, 6 |
| `zeroos/surface/window.py` | close-request now defers to a worker thread. | 6 |

`notice.py` is deliberately free of every other subsystem: it takes a client and a message list and returns strings. That is what makes Task 4 testable without a gate, a store, or a display.

```python
"""The noticing pass. Spec section 4.

One model call per turn, over a filtered transcript, returning facts worth
proposing. It knows nothing about the gate, the store, or the display: it
takes a client and messages and returns strings, which is what lets it be
tested without any of them.

The filter is the security boundary of v0.2.1. Tool results carry file
contents and file contents are attacker-controlled, so a pass that read
them would let text inside a file author a memory proposal -- on every
turn, not once. Only user messages and assistant prose go out.
"""

from zeroos.platform import memory

MAX_CANDIDATES = 2
MAX_TOKENS = 200

INSTRUCTION = (
    "Read this conversation and list any lasting facts about the user worth "
    "remembering for future conversations: where things live, how they work, "
    "what they prefer. One per line, in the user's own words, one sentence "
    "each. List nothing at all if there is nothing lasting -- most "
    "conversations have none. Never list anything the user did not say "
    "themselves, and never list the contents of a file. Reply with the lines "
    "only, no preamble and no numbering."
)


def _readable(messages: list[dict]) -> list[dict]:
    """User messages and assistant prose. Never tool results, never tool_calls.

    An assistant message replays its tool_calls so the results have something
    to attach to; there are no results here, so they are noise that names
    files the user may not have mentioned. Dropped along with the results.
    """
    kept = []
    for message in messages:
        role = message.get("role")
        if role not in ("user", "assistant"):
            continue
        content = message.get("content") or ""
        if content:
            kept.append({"role": role, "content": content})
    return kept


def candidates(client, messages: list[dict]) -> list[str]:
    """Fact candidates from this turn. Never raises.

    A failure returns [], which is indistinguishable from finding nothing --
    and that is right. Nothing in this path may take a turn down, and there
    is nothing a user could do about a failed noticing pass anyway.
    """
    try:
        conversation = _readable(messages)
        if not conversation:
            return []
        from zeroos.agent.session import MODEL

        reply = client.chat.completions.create(
            model=MODEL,
            max_tokens=MAX_TOKENS,
            messages=[{"role": "system", "content": INSTRUCTION}] + conversation,
        ).choices[0].message.content or ""

        found = []
        for line in reply.splitlines():
            text = memory.normalise(line)
            # Dropped, not truncated: truncating changes what a fact says, and
            # the user would be approving text the model did not write.
            if not text or len(text) > memory.MAX_CHARS:
                continue
            found.append(text)
            if len(found) == MAX_CANDIDATES:
                break
        return found
    except Exception:
        return []
```

**Context you need — this is the subtle part of the plan.**

        """Put the previous turn's candidates through the ordinary dialog.

        Runs before the step loop, so the loop's own prepare() clears a ledger
        whose entries have already been consumed. Drained first: offering the
        same candidate twice would ask about a fact already answered.

        spool file this design does without.

        for text in found:

            # remember and belongs in actions.log and the counters like one.
            self._run("remember", {"text": text})

## Task 6: The closing summary

**Files:**
- Modify: `zeroos/agent/session.py` (`close`)
- Modify: `zeroos/surface/window.py:70-73` (`_on_close`)
- Test: `tests/test_session.py`, `tests/test_window.py`

**Interfaces:**
- Consumes: `notice.candidates` (Task 4), `_offer_candidates` (Task 5).
- Produces: `Session.close()` keeps its no-argument, never-raises contract.

**Context you need — there is a deadlock here if this is done naively.**

`window.py:70-73` is:

```python
    def _on_close(self, _window) -> bool:
        self._session.close()
        return False
```

That runs on the **main thread**. `dialog.ask_on_main_thread` does `GLib.idle_add(build)` then `answered.wait()` — called from the main thread, the idle callback can never run, because the main loop is blocked inside `wait()`. **It deadlocks, every time.** The turn path is safe only because `_run_turn` is on a worker thread.

So the close path must: hide the window, halt the close, do the work on a worker thread, then destroy for real.

    def close(self) -> None:
        """Called once, on window shutdown. Never raises.

        Order matters: the closing summary's approved remembers go through
        _run and increment _actions, so usage.record must come last or the
        line undercounts the session it describes.

        there is nothing a user can do about a failed summary at the moment

    def _on_close(self, _window) -> bool:
        """Halt the close, run the closing summary off the main thread, then
        destroy for real.

        session.close() may open the approval dialog, and
        dialog.ask_on_main_thread does GLib.idle_add followed by a blocking
